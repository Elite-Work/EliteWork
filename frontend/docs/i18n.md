# Internationalization (i18n)

EliteWork's core market is Nigeria. All locale-aware output defaults to **`en-NG`**
and **NGN** currency. This document covers adding strings, formatting values, and
contributing translations.

## TL;DR

```ts
import { t, formatNaira, formatDate, formatRelativeTime } from "@/lib/i18n";

t("wallet.connect");                              // "Connect wallet"
t("wallet.wrongNetworkCta", { expected: "Testnet" }); // "Switch to Testnet"
formatNaira(1234.56);                             // "₦1,234.56"
formatDate(trade.createdAt);                      // "29 Aug 2026"
formatRelativeTime(trade.updatedAt);             // "3 days ago"
```

## Module layout

| File | Purpose |
| --- | --- |
| `src/lib/i18n/config.ts` | Default locale/currency, pseudo-locale switch |
| `src/lib/i18n/format.ts` | `Intl`-based money / number / date / relative-time formatters |
| `src/lib/i18n/pseudo.ts` | Pseudo-localization transform |
| `src/lib/i18n/messages/en.ts` | Base (en-NG) message catalog — **source of truth for copy** |
| `src/lib/i18n/index.ts` | `t()` + re-exports |

On-chain asset formatters (`formatXlm`, `formatUsdc`, `formatStroops`) live in
`src/lib/stellar/format.ts` and now delegate grouping to this module.

## Adding a new string

1. Add the key to `src/lib/i18n/messages/en.ts` under the relevant feature
   namespace (`common`, `wallet`, `trade`, …). Use `{placeholder}` for
   interpolated values.
2. Reference it with `t("namespace.key")`. The key type is derived from the
   catalog, so a typo is a compile error.
3. Never ship a raw user-facing literal in JSX. The ESLint rule
   `react/jsx-no-literals` (see `eslint.config` — enable for `src/app` &
   `src/components`) flags them; the pseudo-locale build is the visual backstop.

## Formatting values

- **Money:** `formatNaira(amount)` or `formatMoney(amount, { currency })`.
  Never `toLocaleString("en-US")` — that produces `$` and US grouping.
- **Dates:** `formatDate`, `formatDateTime`, `formatRelativeTime`. All accept a
  `Date`, ISO string, or epoch ms.
- **Numbers:** `formatNumber(value, { maximumFractionDigits })`.

All formatters throw `RangeError` on non-finite / invalid input — pass validated
data or guard first.

## Pseudo-locale (finding hardcoded strings)

Build or run with `NEXT_PUBLIC_PSEUDO_LOCALE=1`:

```bash
NEXT_PUBLIC_PSEUDO_LOCALE=1 pnpm dev
NEXT_PUBLIC_PSEUDO_LOCALE=1 pnpm build   # pseudo smoke build
```

Catalog strings render as `⟦Çöññéçţ ŵåļļéţ ···⟧` — accented and ~35% longer.
Anything still plain ASCII is a hardcoded literal that skipped the catalog, or a
layout that can't absorb longer translations. Run the Playwright visual suite
against this build for the smoke check.

## Contributing a translation

1. Copy `messages/en.ts` to `messages/<locale>.ts` (e.g. `ha.ts` for Hausa,
   `yo.ts` Yoruba, `ig.ts` Igbo, `fr.ts` French), keeping the exact key
   structure.
2. Translate values only — never rename keys or remove `{placeholders}`.
3. Register the catalog in `CATALOGS` in `src/lib/i18n/index.ts` and add the
   locale to `SUPPORTED_LOCALES` in `config.ts`.
4. Keep sentences whole — don't concatenate translated fragments in code.
5. Submit as a PR; a missing key falls back to `en` at runtime and logs a
   `[i18n] missing message key` warning in dev.

## Definition of done checklist

- [ ] No raw user-facing literals outside the catalog (lint-enforced)
- [ ] Money renders as `₦1,234.56` everywhere
- [ ] `NEXT_PUBLIC_PSEUDO_LOCALE=1 pnpm build` passes visual smoke
- [ ] New strings documented here if they introduce a namespace
